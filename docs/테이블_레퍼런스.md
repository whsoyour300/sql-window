# 테이블 레퍼런스 — customers · support_tickets · usage_monthly

다음에 이 테이블을 쓰는 Claude가 먼저 읽는 문서다. 숫자는 edata9-data 도구로 SQL로 센 것만 적었다. 짐작은 «짐작» 이라고 표시했다.
기준: 고객 50,000명 · 기간 2025-01 ~ 2025-12.

---

## customers

| 항목 | 내용 |
|---|---|
| 그레인 | 고객 1명 = 1행 |
| 키 | `customer_id` — 50,000행 = 고유 50,000 (중복 · 결측 0) |
| 규모 | 50,000행 · 13컬럼 |
| 기간 | 가입일 2018-12-25 ~ 2025-12-31 · 이탈일 2025-01-01 ~ 2025-12-31 |
| 이탈 | `is_churned` true 7,256 / false 42,744 (is_churned 와 churn_date 는 어긋남 0) |

**컬럼**: customer_id · customer_name · visitor_id · signup_date · acquisition_channel · campaign_id · plan_type · monthly_fee · age_group · region · device_os · is_churned · churn_date

**결측**: visitor_id 43,515 · campaign_id 43,515 · churn_date 42,744. 나머지 10컬럼은 0.

**값 분포**
- acquisition_channel: 검색 17,416 / 디스플레이 11,571 / 제휴 9,516 / 추천 7,460 / 오프라인 4,037
- plan_type: LTE기본 13,781 / LTE무제한 12,404 / 5G스탠다드 10,953 / 알뜰 7,711 / 5G프리미엄 5,151
- age_group: 30대 13,026 / 40대 12,064 / 20대 10,887 / 50대 9,029 / 60대이상 4,994
- device_os: Android 30,925 / iOS 19,075
- monthly_fee: 19,000(7,711) · 33,000(13,781) · 45,000(12,404) · 55,000(10,953) · 89,000(5,151). region 은 17개(경기 12,940 · 서울 9,526 · 부산 3,523 … 세종 461)

**월별 가입**: 85개월(2018-12 ~ 2025-12), 빠진 달 0. 2019-01 이후 월 25 ~ 667건. 적은 달: 2024-12 = 25건(12/3 ~ 12/31 가입 0건) · 2018-12 = 133(12/25 시작) · 2025-01 = 345 · 2025-02 = 401.

**조인**: 기준 테이블. 다른 테이블과 `customer_id` 로 잇는다.
- customers 1 : support_tickets 0..N — customers 기준 LEFT JOIN 59,391행 (티켓 없는 고객 26,602 + 티켓 32,789)
- customers 1 : usage_monthly 0..12 — customers 기준 LEFT JOIN 523,840행 (usage_monthly 523,825 + 이용 기록 없는 고객 15명)

**쓰면 안 되는 컬럼과 이유**
- `visitor_id` · `campaign_id` — 2025 가입자 6,485명에게만 채워짐. 2018~2024 가입 43,515행(87%)은 전부 결측. 전체 고객 유입 분석에 못 씀. 오프라인 채널 4,037 중 557건에도 campaign_id 가 있어 «캠페인 유입» 과 같은 뜻이 아님.
- `is_churned` · `churn_date` — 이탈이 2025년에만 기록됨. 2025년 이전 이탈은 기록이 없다. 전체 기간 이탈률 · 생존 분석에 못 씀.
- `monthly_fee` — plan_type 과 1:1 (불일치 0). 새 정보가 없고 요금 이력 · ARPU 변화 분석에 못 씀.
- `customer_name` — 고유 22,742. 키가 아님(동명이인).

**데이터를 만든 사람에게 물을 것**
1. 2024-12-03 ~ 2024-12-31 가입이 0건인 이유 (적재 누락인가, 실제인가)? 2025-01 · 02 가 낮은 이유는?
2. churn_date 가 2025년에만 있는 이유. 2025년 이전 이탈은 삭제되었나, 2025년 초 활성 고객만 추렸나?
3. visitor_id · campaign_id 가 2025 가입자에게만 있는 이유. 오프라인 채널에 campaign_id 가 있는 뜻은?
4. monthly_fee 는 가입 시점 값인가 현재 값인가? 요금제 변경 이력은 어디에 있나?
5. 2018-12-25 시작(133건)은 시스템 오픈일인가, 추출 범위 때문인가?

## support_tickets

| 항목 | 내용 |
|---|---|
| 그레인 | 상담 문의 1건 = 1행 |
| 키 | `ticket_id` — 32,789행 = 고유 32,789. 외래키 customer_id(고유 23,398) · agent_id(고유 120) |
| 규모 | 32,789행 · 10컬럼 (결측 0) |
| 기간 | created_date 2025-01-01 ~ 2025-12-31, 12개월 모두 있음 |

**컬럼**: ticket_id · customer_id · agent_id · created_date · contact_channel · ticket_category · duration_min · resolution_hours · status · is_recontact

**값 분포**
- contact_channel: 전화 14,324 / 챗봇 7,967 / 앱 6,865 / 이메일 3,633
- ticket_category: 요금 10,166 / 품질 7,794 / 가입변경 6,220 / 기타 4,349 / 해지 4,260
- status: 완료 29,772 / 진행중 2,002 / 보류 1,015
- is_recontact: false 25,362 / true 7,427
- duration_min 1 ~ 80 · resolution_hours 0.2 ~ 97.1

**월별 건수**: 1월 2,686 · 2월 2,539(최소) · 3월 2,821 · 4월 2,749 · 5월 2,634 · 6월 2,687 · 7월 2,781 · 8월 2,819 · 9월 2,689 · 10월 2,794 · 11월 2,707 · 12월 2,883(최대). 빠진 달 · 눈에 띄게 적은 달 없음.

**조인**
- support_tickets N : customers 1 (다대일). customers 에 없는 customer_id 0개. support_tickets 기준 LEFT JOIN customers = 32,789행 (불어남 없음).
- customers 기준 LEFT JOIN support_tickets = 59,391행. 티켓 없는 고객 26,602명. 고객 단위로 집계하려면 티켓 쪽을 customer_id 로 먼저 집계한 뒤 붙인다.
- agents 조인 32,789행 전부 매칭. 가입일 이전 티켓 0건 · 이탈일 이후 티켓 0건.

**쓰면 안 되는 컬럼과 이유**
- `resolution_hours` — 진행중 2,002건 · 보류 1,015건에도 값이 전부 있고 평균이 완료(14.5h)와 같다(진행중 13.9h · 보류 14.1h). 의미가 불명확.
- `duration_min` — 채널과 상관없이 분포가 같다(이메일 · 챗봇도 평균 13.2~13.3분으로 전화와 비슷). 처리 시간(분 → 시간)이 resolution_hours 보다 큰 건 68건. 정의 확인 전에는 채널별 비교에 못 씀.
- `is_recontact` — true 7,427건 중 같은 고객의 이전 날짜 티켓이 이 표에 없는 건이 5,344건. 티켓이 그 고객 1건뿐인데 true 인 건이 3,603건. 이 표 밖 이력일 수 있어(짐작) 재문의율로 못 씀.
- `ticket_category = '해지'` — 해지 문의 4,260건 중 3,911건(약 92%)이 이탈하지 않은 고객. 이탈 지표로 못 씀.

**데이터를 만든 사람에게 물을 것**
1. 진행중 · 보류 건의 resolution_hours 는 무엇인가(예상값 · 경과 시간 · 임의 채움)?
2. duration_min 은 무엇의 시간인가? 이메일 · 챗봇도 전화와 같은 분포인 이유는? 일부가 resolution_hours 보다 긴 이유는?
3. is_recontact 의 기준은(같은 고객 · 같은 카테고리 · 며칠 이내)? 2025년 이전 이력을 포함하나?
4. «해지» 는 해지 문의인가 해지 처리인가? 대부분 is_churned = false 인 이유는?
5. 진행중 · 보류는 추출 시점 기준인가? 완료 시점 컬럼이 없는 이유는?

## usage_monthly

| 항목 | 내용 |
|---|---|
| 그레인 | 고객 × 월 1행 |
| 키 | (`customer_id`, `year_month`) — 523,825행 = 고유 조합 523,825 |
| 규모 | 523,825행 · 9컬럼 (결측 0) · 고유 customer_id 49,985 · year_month 12개 |
| 기간 | year_month 2025-01 ~ 2025-12 (문자열 'YYYY-MM'), 빠진 달 없음 |

**컬럼**: customer_id · year_month · data_gb · voice_min · sms_count · billing_amount · app_login_count · service_count · is_active

**범위**: data_gb 0.23 ~ 128.27 · voice_min 55 ~ 239 · sms_count 0 ~ 32 · billing_amount 10,450 ~ 100,480 · app_login_count 0 ~ 36 · service_count 0 ~ 12 · is_active 전부 true(523,825건).

**월별 건수**: 1월 43,845 · 2월 43,685 · 3월 43,795 · 4월 43,790 · 5월 43,793 · 6월 43,707 · 7월 43,654 · 8월 43,610 · 9월 43,562 · 10월 43,509 · 11월 43,463 · 12월 43,412. 7월부터 매달 줄어든다.

**조인**
- customers 1 : usage_monthly 0..12. usage_monthly 에는 있고 customers 에는 없는 키 0개.
- customers 에만 있고 usage_monthly 에 없는 고객 15명 (50,000 − 49,985). **INNER JOIN 을 하면 이 15명이 조용히 빠진다.**
- usage_monthly 기준 LEFT JOIN customers = 523,825행 (불어남 없음).
- customers 기준 LEFT JOIN usage_monthly = 523,840행. **고객 단위 값(monthly_fee 등)을 조인 뒤 SUM 하면 월 수만큼 겹쳐 더해진다.**
- 가입 전 월의 행 0건 · 이탈 월 이후의 행 0건 (정상).

**쓰면 안 되는 컬럼과 이유**
- `is_active` — 전부 true 라 정보가 없다. 이탈 고객의 행도 true (customers.is_churned = true 인 고객의 행 46,280개). app_login_count 가 0 인 131행도 true.
- `service_count` — 0 인 행이 47,425개인데 모두 billing_amount > 0 이고 data_gb · voice_min 도 0 보다 크다. 뜻을 확인하기 전에는 쓰지 않는다.
- `billing_amount` — customers.monthly_fee 와 같은 행 12,848 · 다른 행 510,977, 최솟값 10,450 (0원 없음). «월 요금» 이라 부르기 전에 정의를 확인한다. 별도 청구액으로 보이지만 짐작이다.

**데이터를 만든 사람에게 물을 것**
1. is_active 가 전부 true 인 이유와 정의. 이탈 고객 행도 true 인 이유는?
2. service_count 0 은 무엇인가? 서비스가 0개인데 요금 · 사용량이 있다(47,425행).
3. billing_amount 는 무엇을 합친 금액인가(기본 요금 · 사용량 요금 · 부가세)? monthly_fee 와 다른 행이 대부분인 이유는?
4. 고객 15명이 usage_monthly 에 한 번도 없는 이유(미사용 · 추출 누락)? 7월 이후 월별 행 수가 줄어드는 것이 이탈 때문인가?
5. 이탈 월에는 사용 행이 남나, 이탈 전 월까지만 있나?

## 분석 전에 알아 둘 것

1. 이탈은 2025년에만 기록돼 있다 — 2025 이전 이탈은 알 수 없으니 이탈률은 «2025년 한 해» 로만 말한다.
2. 고객 단위 값(monthly_fee 등)을 usage_monthly 에 조인한 뒤 SUM 하면 월 수만큼 불어난다. 고객 단위로 먼저 집계한 뒤 붙인다.
3. usage_monthly 에 INNER JOIN 하면 이용 기록이 없는 15명이 빠진다(49,985명). 전체 고객이 필요하면 LEFT JOIN.
4. support_tickets 를 고객 단위로 쓸 땐 customer_id 로 먼저 집계한다 — 티켓 없는 고객이 26,602명이다.
5. is_active · service_count · resolution_hours · duration_min · is_recontact · billing_amount · «해지» 카테고리는 정의 확인 전에는 지표로 쓰지 않는다.
